## fullstack-tasks 全棧應用腳手架（新建於 APP_!/fullstack-tasks）

從 WAVE ART MALL 範本需求長出的獨立全棧子專案（Express + PGlite 本機 Postgres + 多頁 Tailwind 前端），放在 APP_! 工作區內獨立資料夾，不干擾範本既有的 vercel / gates。

技術決策（使用者選的）：通用任務 CRUD 骨架、HTML+Tailwind+自帶後端（非 Supabase）、PGlite 本機 Postgres。

### 實跑結果（全綠）
- `npm run migrate`：套用 001_init（users / tasks / refresh_tokens + 索引）
- `npm run seed`：建 admin@example.com / member@example.com（密碼 Passw0rd!demo）+ 5 筆示範任務
- `npm run test`：unit 18 + integration 12 全過
- `npm run smoke`：31 項端到端全過（註冊/登入/CRUD/資料隔離/403/管理後台/刪除/回應格式）
- 實機啟動：/health、各靜態頁、/js/api.js 皆 200；未授權 /api/tasks → 401

### 踩坑（已修，下次直接避開）
1. **PGlite 不遞迴建父目錄**：`.data/pgdata` 父層不存在會 ENOENT。已在 `server/db/client.js` 的 initDb 先 `mkdirSync(dirname(dataDir), {recursive:true})`。
2. **migrate 區段切分用 indexOf 撞子串**：註解裡寫「-- ===== UP ===== 以下為…」會讓 `splitSections` 從錯誤位置切開報 syntax error。已改為整行正則 `/^[ \t]*--[ \t]*=====[ \t]*UP[ \t]*=====/m`，並清理註解文字。
3. **client.query 回傳陣列本身**（非 pg 的 `{rows}`）：seed 用 `const {rows}=` 解構會 undefined[0]。已改 seed 直接 `const rows = await query(...)`。
4. **parsePagination 的 `|| 20` 陷阱**：明確傳 pageSize:"0" 被誤填成 20（應夾到下限 1）。已改為 `Number.isFinite(rawSize) ? rawSize : 20`。
