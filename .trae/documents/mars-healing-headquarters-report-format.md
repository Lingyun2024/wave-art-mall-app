# 火星療癒總部呈報格式調整計畫

## Summary

將目前火星療癒管理端的簡易 HTML 資料表，調整為依照既有範本 `G:\草稿\知識庫\靈修\掃瞄11508\S__73244756_0.jpg` 的總部呈報格式輸出。資料來源仍為 Supabase 的 `mars_healing_registrations`，輸出全部登記資料，固定每頁 10 位；不足 10 位時保留空白列，讓總部清楚知道本次實際呈報人數。分會名稱固定為「大直分會」，日期使用呈報／列印當天日期，客戶照片也要套入。最終透過瀏覽器列印流程產生 PDF。

## Current State Analysis

- 主要輸出頁為 `pages/admin-mars-healing.html`。
- 目前頁面已完成管理員 Email 檢查，查詢 `mars_healing_registrations` 全部資料，依 `created_at` 遞增排序。
- 目前輸出是一般 A4 HTML 表格，每頁最多 10 筆，但不是總部範本格式，也沒有不足 10 筆的空白列。
- 目前已使用私有 Storage bucket `mars-healing-photos` 的 signed URL 顯示客戶照片。
- `backend/mars_healing_production.sql` 已確認資料欄位包含姓名、虛歲、電話、職業、地址、照片、登記日期與狀態等可供輸出的資料。
- `pages/admin-roster.html` 已有入口按鈕，導向 `admin-mars-healing.html`，不需要更改入口架構。
- 專案現有驗證指令包括 `npm run lint`、`npm run check:links`、`npm run check:html`、`npm run build`、`npm run test:e2e`。

## Proposed Changes

### 1. 調整 `pages/admin-mars-healing.html`

- 保留現有管理員權限檢查與 Supabase 查詢，不擴大一般使用者權限。
- 將輸出資料模型整理為範本需要的欄位：
  - 客戶照片
  - 姓名
  - 虛歲
  - 電話
  - 地址
  - 職業
  - 呈報日期
- 加入固定設定：
  - 分會名稱：`大直分會`
  - 每頁資料列：10 位
  - 呈報日期：按下載入／輸出時的當天日期
- 依照範本圖片重新安排標題、分會名稱、呈報日期、欄位順序、框線、照片區域與文字區域。
- 使用先前指定的掃描範本作為視覺和欄位定位依據；若瀏覽器端直接使用本機 `G:` 路徑不可行，則將範本以專案可部署的靜態資產方式納入，並使用 CSS 背景或明確的 HTML 欄位覆蓋層承載資料。
- 每頁固定產生 10 個客戶欄位：
  - 有資料的列填入客戶文字與照片。
  - 不足的列保留空白欄位，不重排、不隱藏，讓總部看得到本頁實際呈報數量。
- 超過 10 筆時，依每 10 筆切分成多頁，每頁套用相同範本結構與頁碼。
- 保留「重新載入」及「列印／另存 PDF」操作。
- 列印樣式只保留呈報頁面，隱藏管理工具列與狀態文字，避免工具列出現在 PDF。
- 文字內容全部使用 HTML escaping，照片使用已存在的 signed URL 流程，避免把未授權圖片公開。

### 2. 範本資產處理

- 在執行階段確認 `S__73244756_0.jpg` 的實際版面、尺寸與欄位位置。
- 不直接依賴使用者電腦上的 `G:` 路徑，避免正式 Vercel 站點無法讀取本機檔案。
- 以不破壞既有資產結構的方式，將必要範本資產放到專案既有 assets 目錄；若範本不適合作為背景，則只依其版面重建可列印 HTML，以確保文字與照片清晰。

### 3. 輸出與資料規則

- 輸出範圍：全部 `mars_healing_registrations` 登記資料。
- 排序：維持目前建立時間遞增，讓呈報順序穩定。
- 每頁：固定 10 位，空缺位置填空白。
- 日期：使用呈報日期，不使用每筆登記日期。
- 分會：固定顯示「大直分會」。
- 照片：有照片則依範本照片框比例裁切或縮放；沒有照片則保留空白框，不顯示錯誤文字。
- PDF：使用瀏覽器列印對話框的「另存為 PDF」，不新增外部 PDF 套件，避免引入未確認的依賴。

## Assumptions & Decisions

- 「就是之前那張」指 `G:\草稿\知識庫\靈修\掃瞄11508\S__73244756_0.jpg`。
- 你明確指定每頁仍為 10 位，即使掃描範本視覺上可能有較少的主要區塊；實作會以 10 位固定欄位呈報為準，並保留不足部分的空白。
- 分會名稱固定為「大直分會」。
- 日期固定使用呈報日期。
- 輸出全部登記資料，不新增勾選篩選功能。
- 本階段只做 PDF 列印輸出，不另做 PNG/JPG 匯出。
- 不修改 Supabase schema 或 RLS，因目前欄位和權限已足以支援呈報輸出。
- 不修改使用者登記頁、成功頁與歷史頁，避免影響已部署功能。

## Verification Steps

1. 讀取並確認範本尺寸、比例、標題、分會、日期與資料區塊位置。
2. 以目前 2 筆資料載入管理端，確認同一頁產生 10 個固定位置，其中 2 位有資料、其餘 8 位為空白。
3. 確認兩位客戶照片能載入，並且不會把私有 Storage URL 暴露成永久公開 URL。
4. 建立或使用超過 10 筆資料的測試情境，確認自動產生第二頁，且每頁仍固定 10 位。
5. 確認每頁顯示「大直分會」與呈報當天日期。
6. 使用瀏覽器列印預覽確認 A4 分頁、範本比例、文字不裁切、照片不溢出、空白列保留。
7. 執行 `npm run lint`。
8. 執行 `npm run check:links`、`npm run check:html`、`npm run build`；若既有 E2E 環境可用，再執行 `npm run test:e2e`。
9. 部署後使用正式網址登入管理員帳號，重新整理並測試「列印／另存 PDF」。
