# 火星療癒登記管理與總部報表規範

更新日期：2026-09-30

## 一、規範目的

本文件是火星療癒登記、歷史資料管理及總部 A4 報表的固定實作與驗收標準。

後續修改必須以本文件為準，不得再以目測方式反覆猜測照片大小、裁切量、欄位位置或資料處理方式。若需求改變，必須先更新本規範，再修改程式。

## 二、頁面職責

### 1. 使用者登記頁

檔案：`pages/mars-healing-register.html`

用途：

- 填寫火星療癒登記資料。
- 上傳個人照片。
- 填寫匯款末五碼與相關備註。
- 將資料寫入 `mars_healing_registrations`。
- 網路錯誤時顯示可理解的繁體中文訊息，並允許有限次數重試。

### 2. 使用者歷史資料頁

檔案：`pages/mars-healing-history.html`

用途：

- 使用者只能查看自己的登記紀錄。
- 待處理資料可修改允許的付款資訊。
- 使用者取消登記時採狀態取消，不直接永久刪除資料。

### 3. 管理頁

檔案：`pages/mars-healing-admin.html`

用途：

- 查詢全部歷史登記資料。
- 依姓名、電話、地址搜尋。
- 依付款狀態與審核狀態篩選。
- 查看私人照片。
- 修改登記資料。
- 將資料移到已取消。
- 恢復已取消資料。
- 匯出 CSV。

### 4. 總部 A4 報表頁

檔案：`pages/admin-mars-healing.html`

用途：

- 只輸出審核通過且付款已核對的資料。
- 套用總部報表背景範本。
- 每頁固定容納 10 位客戶。
- 透過瀏覽器列印或另存 PDF。

## 三、資料輸出條件

總部報表只允許以下資料進入：

```text
registration_status = approved
payment_status = verified
```

排序方式：

```text
created_at 由舊到新排列
```

已提交、審核中、已取消、付款待核對或付款核對失敗的資料，不得出現在總部報表。

## 四、A4 報表固定規格

### 1. 紙張與背景

- 紙張尺寸：A4。
- 寬度：`210mm`。
- 高度：`297mm`。
- 列印邊界：`0`。
- 背景範本：`assets/mars-healing/headquarters-report-template.jpg`。
- 背景必須完整覆蓋 A4 頁面。
- 每頁固定 10 位，前 5 位在上半部，後 5 位在下半部。
- 不足 10 位時保留空白位置，不得壓縮或重新排列。

### 2. 分會名稱與報表日期

- 分會名稱固定顯示：`大直`。
- 不顯示「分會」二字。
- 分會名稱字體：`22px`、粗體、紅色。
- 分會名稱位置以目前核准的 CSS 位置為準。
- 報表日期使用產生報表當天日期。
- 報表日期不得取代每筆客戶原始登記時間。

## 五、照片固定規範

### 1. 原始規格與裁切

每張照片均使用相同規格：

| 項目 | 固定值 |
|---|---:|
| 原始目標寬度 | `35mm` |
| 原始目標高度 | `45mm` |
| 左側裁切 | `1.5mm` |
| 右側裁切 | `1.5mm` |
| 高度裁切 | `5mm` |
| 最終顯示寬度 | `32mm` |
| 最終顯示高度 | `40mm` |
| 垂直位置 | 上移 `1.5mm` |

計算方式：

```text
照片寬度 = 35mm - 1.5mm - 1.5mm = 32mm
照片高度 = 45mm - 5mm = 40mm
```

### 2. 裁切方式

固定使用：

```css
object-fit: cover;
object-position: center top;
```

目的：

- 照片不得被拉長或壓扁。
- 超出的部分直接裁切。
- 優先保留人物頭部與照片上方內容。
- 照片不得超出紅色照片框。

### 3. 每欄固定水平位置

| 欄位 | 水平位移 |
|---|---:|
| 第1欄 | 左移 `1mm` |
| 第2欄 | 左移 `1mm` |
| 第3欄 | 左移 `3mm` |
| 第4欄 | 左移 `1mm` |
| 第5欄 | 左移 `1mm` |

下半部位置沿用上半部相同欄位規則：

- 第6張沿用第1欄。
- 第7張沿用第2欄。
- 第8張沿用第3欄。
- 第9張沿用第4欄。
- 第10張沿用第5欄。

### 4. 維護方式

照片尺寸、裁切量及位置必須集中寫在 CSS 變數中。

後續若要調整，只能修改集中變數，不得重新加入分散的單張照片尺寸或臨時 `transform` 規則。

## 六、文字紅框規範

### 1. 適用欄位

- 姓名
- 虛歲
- 電話
- 地址
- 職業
- 日期

### 2. 欄位寬度

- 每格最大寬度：約 `30.8mm`。
- 文字不得超出紅框。
- 長文字必須自動換行。
- 中文、英文、數字或沒有空格的連續內容，都必須能斷行。

固定換行規則：

```css
overflow: hidden;
overflow-wrap: anywhere;
word-break: break-all;
white-space: normal;
```

### 3. 自動字體大小

- 初始字體：`16px`。
- 若文字超出欄位寬度或高度，每次縮小 `0.5px`。
- 最小字體：`8px`。
- 應在紅框寬度與高度允許的情況下，使用可容納內容的最大字體。
- 不得為了塞入內容而讓文字跨入其他欄位。

### 4. 已核准的垂直位置

| 欄位 | CSS 垂直位置 |
|---|---:|
| 姓名 | `top: -5mm` |
| 虛歲 | `top: -6mm` |
| 電話 | `top: -8mm` |
| 地址 | `top: -7mm` |
| 職業 | `top: -11mm` |
| 日期 | `top: -14mm` |

這些位置是目前逐項核准結果。後續調整必須記錄新的毫米數值，不得使用「上移幾行」作為程式規格。

## 七、管理端歷史查詢規範

管理頁必須支援：

- 顯示全部歷史資料，包括已取消資料。
- 依姓名搜尋。
- 依電話搜尋。
- 依地址搜尋。
- 依登記狀態篩選。
- 依付款狀態篩選。
- 依建立時間由新到舊排列。
- 可查看每筆資料的完整內容及照片。

搜尋或篩選後，統計數字與 CSV 匯出內容應以目前畫面上的查詢結果為準。

## 八、管理端資料修改規範

管理員可在網頁中修改，不得要求管理員進入 Supabase 後台處理一般資料錯誤。

允許修改：

- 代表人姓名
- 虛歲
- 聯絡電話
- 職業
- 通訊地址
- 代理人
- 匯款末五碼
- 轉帳備註
- 請領備註
- 付款狀態
- 審核狀態
- 管理備註

儲存時必須驗證：

- 代表人姓名不可空白。
- 虛歲必須是正整數。
- 聯絡電話不可空白。
- 通訊地址不可空白。
- 匯款末五碼必須剛好是 5 位數字。

儲存成功後必須：

- 更新畫面資料。
- 更新 `reviewed_by`。
- 更新 `reviewed_at`。
- 顯示明確成功訊息。

儲存失敗時必須：

- 保留使用者正在修改的內容。
- 顯示可理解的錯誤訊息。
- 不得在失敗時顯示成功或關閉視窗。

## 九、取消與恢復規範

### 1. 移到已取消

管理頁的「刪除」採安全取消，不做永久刪除。

執行前必須顯示確認視窗。確認後設定：

```text
registration_status = rejected
payment_status = rejected
```

並在管理備註中留下可辨識的取消紀錄與時間。

效果：

- 資料保留在歷史紀錄中。
- 不再進入總部報表。
- 可由管理員恢復。
- 私人照片不刪除。

### 2. 恢復

已取消資料必須顯示「恢復」按鈕。

執行前必須顯示確認視窗。確認後設定：

```text
registration_status = submitted
payment_status = pending
```

並在管理備註中留下恢復紀錄與時間。

恢復後仍需重新審核與核對付款，不得直接恢復成已通過或已付款。

## 十、安全與權限規範

- 一般使用者只能查看自己的資料。
- 一般使用者不得修改其他人的資料。
- 管理功能只允許管理員帳號使用。
- 真正的權限保護必須由 Supabase RLS 執行，不能只依賴前端隱藏按鈕。
- 照片 Storage 必須維持 Private bucket。
- 照片只透過短效 signed URL 顯示。
- 不得將 Supabase Secret Key、Personal Access Token 或其他秘密寫入 HTML、Git 或規範文件。
- 不得在未確認的情況下永久刪除客戶資料與照片。

## 十一、驗收標準

### 1. 管理功能驗收

- 管理員能在網頁查到全部歷史資料。
- 姓名、電話、地址搜尋正常。
- 付款與審核狀態篩選正常。
- 可以修改全部指定欄位。
- 不合法資料會被阻止儲存。
- 可將資料移到已取消。
- 已取消資料不會出現在總部報表。
- 可恢復已取消資料。
- 恢復後狀態為已提交、待核對。

### 2. 報表驗收

最終版面一律以瀏覽器的 A4 列印預覽為準，不以一般網頁縮放畫面作為最後標準。

必須確認：

- A4 尺寸與背景範本完全對齊。
- 每頁固定 10 位。
- 照片最終尺寸為 `32mm × 40mm`。
- 照片不變形、不超框。
- 第1至第5欄及第6至第10欄位置符合固定規則。
- 姓名、虛歲、電話、地址、職業與日期均在紅框內。
- 長地址和長姓名能自動換行。
- 字體只在必要時縮小，且不得小於 `8px`。
- 分會名稱顯示「大直」。
- 工具列及狀態文字不出現在列印頁面。

### 3. 程式檢查

每次修改後至少執行：

```powershell
npx prettier --check pages/mars-healing-admin.html pages/admin-mars-healing.html
npx html-validate pages/mars-healing-admin.html pages/admin-mars-healing.html
npm run build
git diff --check
```

若修改其他頁面，必須將其他頁面加入相同格式與 HTML 檢查。

## 十二、變更控制

- 不得因修正管理功能而任意重做報表版面。
- 不得因修正報表版面而破壞歷史查詢、修改、取消或恢復功能。
- 不得新增另一個功能重複的管理頁。
- 應優先修改現有頁面與沿用現有 Supabase 資料表。
- 使用者手動修改的內容不得未經確認被覆蓋。
- 提交 Git 或推送 GitHub／Vercel 前，必須取得使用者明確同意。
- 每次版面調整都要記錄精確的 `mm`、`px` 或百分比，不使用「一行」、「一點」等無法重現的描述。
