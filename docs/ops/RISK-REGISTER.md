## 二、AI 幻覺防護

> 本站版本＝「內容查證事實溯源」，不是只檢格式

| 檢查項 | 本站做法 | 狀態 |
|---|---|---|
| 事實查核 | `docs/content-audit.md` 每條發現標註「查證來源」（如 grep 全站、比對歷史版本） | ✅ |
| 來源可追溯 | 每條 A/P 級發現附檔案路徑與行號 | ✅ |
| 邊界聲明 | 「判不出」的項目標為**待決**，不猜（例：holiday 疊字全歷史版本一致 → 保留待決） | ✅ |
| 交叉驗證 | 使用者回饋級查證（「執執登記名冊」查 `_local_backup/MD_SP/造新字.md` 證實是主動改名，非疊字錯誤） | ✅ |

**紅線**：任何「我覺得應該是 X」的結論，沒有檔案證據 → 不得寫進正本。

## 三、SOP 僵化防護

| 機制 | 站上載體 | 修訂觸發 |
|---|---|---|
| 凍結契約 | `out/rewrite/base/CONTRACT.md`（R1–R7 評審紅線） | 模組開發發現紅線不足或過嚴 |
| 決策記錄 | `docs/decisions/ADR-000X` | 出現新的不可逆選型 |
| 未決登記 | `docs/ops/OPEN-DECISIONS.md` | 定不下來就落條，不硬猜 |
| 門檻腳本 | `tools/` + `package.json` scripts | 出現新類型的低級錯誤 |

**修訂流程**（沿用專案既有節奏）：
1. 發現 → 落 `OPEN-DECISIONS.md`
2. 影響範圍判定（1 頁 / 1 模組 / 全站）
3. 全站級 → 開新 ADR，族族拍板
4. 模組級 → 更新 CONTRACT.md，commit
5. 舊版保留於 git，可 rollback

| R4 | 改 token 忘記重編 CSS | 樣式全壞 | `.sources.sha256` hash 檢查 | ✅ |
| R5 | 四項文案決策卡住技術線 | 模組停擺 | 登記 OPEN-DECISIONS | 🔴 **無逾期規則** |
| R6 | 線上異常無人告警 | 故障靠人發現 | 無 | 🔴 **監控缺失** |
| **R7** | **銀行帳號曾進本地 git 歷史** | 若日後 push 到遠端即公開 | 2026-09-22 已從頁面移除；**實測線上 9 頁（含原 4 頁）零命中帳號／渣打／大直分行，且修正文案「承辦人員」已上線** → 公開面已乾淨。`git log -S 12120000002912` 顯示曾存在於 52137f3／73c41f6 | 🟢 **對外無暴露**；剩餘風險僅本機 git 歷史（無遠端、從未 push）。**本站上線走 Vercel CLI 上傳、不走 git push** → 日常部署不會外洩；只有在「日後把此 repo 推到任何遠端」之前才需清歷史 |
| **R9** | **評價功能形同停用**：`pages/review.html` 已上線並已部署，但 `reviews_policy_patch.sql` 從未執行 | 用戶送出評價被 RLS 擋下，功能看似存在實則壞掉 | 無（前端已就緒，只差 policy） | 🔴 **未執行**（2026-09-22 盤點時發現先前漏登記） |
| **R8** | **SQL 未測即上線**（v1 若照原樣執行，商城結帳 100% 失敗） | 全站無法收款 | v1 缺陷已於 2026-09-22 本地 PGlite 實測抓出並修正為 v2；`npm run test:money` 已納 gates | ✅ **已緩解**（v2 尚未上線，仍待族族執行） |

> **R8 原委**：v1 把結算掛在 `orders` 的 `DEFERRABLE INITIALLY DEFERRED` 約束觸發器，而 PostgREST 每次請求各自提交，
> checkout 先插 orders 後插 order_items → 第一次提交時明細尚空 → 拋「沒有任何訂單項目」→ 真實結帳全掛。
> v1 在「同一交易內插完」的單元情境會通過，只有模擬真實時序（T4）測得到。**教訓：DB 防線必須照真實時序測，不能只測理想情境。**
