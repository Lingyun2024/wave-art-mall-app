   - 6个身份选项按钮
   - 视频继续播放

4. **填写资料结账页** (`pages/holiday-form.html`)

   - 管理员名册可查看地赦订单、后五码，并标记已汇款

✅ **修复4**: 订单更新权限 (RLS) 全站性错误 — **重要**
- 问题: 原策略为 `USING (auth.uid() = user_id AND status = 'pending')`，但本系统 `orders.status` 实际使用**中文值**（`待處理` / `待付款` / `已出貨` / `已完成` / `已取消`，见 `order-history.html` 的 `STATUS_LABEL_MAP`）。英文 `'pending'` 永远匹配不到，导致**全站每一笔客户订单更新都被拒绝**（含取消订单、保存汇款后五码）
- 修复: 改以恒为英文的付款状态为判断依据 —— `USING (auth.uid() = user_id AND payment_status = 'pending')`，并同步加上 `WITH CHECK` 相同条件（顺带防止客户自行把订单改为已付款）
- 文件: `backend/supabase-schema.sql` (第358-361行) + `backend/holiday_admin_patch.sql` (第20-24行)
- 备注: `orders.status` 无 CHECK 约束，中文状态值可正常写入；`payment_status` 默认值即 `'pending'`，故一般商品订单不受影响

✅ **修复5**: 地赦订单落库与后台名册
- 身分 / 虚岁 / 代理人随 `orders` 一次写入专属字段；若线上补丁尚未执行，自动降级改写 `customer_note` 兼容保存（错误码 `42703` / `PGRST204` 时重试），客户端不会下单失败

## 🆘 常见问题排查

### 问题1: 页面空白或加载失败
- 检查是否启动了本地服务器
- 检查控制台是否有错误信息
- 确认网络连接正常 (需要加载CDN资源)

### 问题2: 登录/注册失败
- 检查邮箱格式是否正确
- 检查密码是否符合要求 (至少6位)
- 确认已查收验证邮件

### 问题3: 购物车功能异常
- 确认已登录
- 检查浏览器控制台错误
- 确认Supabase数据库连接正常

### 问题4: 订单历史显示为空
- 确认已完成至少一笔订单
- 刷新页面重新加载

### 问题5: 汇款后五码保存失败 / 名册页一片空白
**90% 是 `backend/holiday_admin_patch.sql` 尚未在 Supabase 执行**
- 症状A（后五码存不了）: 补丁内的 RLS 修正未生效，或该订单已被标记为「已汇款」（`payment_status = 'paid'` 后即禁止客户再改，需由管理员处理）
- 症状B（名册空白）: 管理员跨用户查询策略未建立，RLS 只让人看到自己的订单
- 症状C（身分/虚岁/代理人栏位空）: `identity_type` / `age` / `agent_name` 字段尚未新增，资料已降级保存在该笔订单的 `customer_note` 内，执行补丁后新订单即正常
- 解法: 登录 Supabase 后台 → SQL Editor → 贴上并执行 `backend/holiday_admin_patch.sql`

### 问题6: 管理员登录后仍进不了名册页
- 确认登录邮箱与 `pages/admin-roster.html` 及补丁 SQL 内的白名单邮箱**完全一致**（预设 `2022lingyun@gmail.com`）
- 若更换管理员邮箱，需同时修改两处：名册页的前端白名单、补丁 SQL 的两条 `Admins can ...` 策略，并重新执行该 SQL
