## 二、問題清單（依嚴重度）

### 🔴 P0 — 建議立刻處理

1. **同埠 8765 有 2 個行程同時監聽**
   Windows 的 `SO_REUSEADDR` 讓兩個 `http.server` 同時綁住 8765。目前兩者恰好服務同一目錄所以看不出異狀，但只要其中一個是在別的目錄啟動的，就會出現「改了檔案卻看到舊版」的鬼打牆。
   → 建議：保留一個，另一個 kill 掉（需先確認各自的 cwd）。

2. **硬體碟上有一支 613MB 的 `assets/videos/mars-healing-v34.mp4`**
   `.vercelignore` 已排除 `assets/videos`，所以不會上線、也不是壞檔，純粹是佔空間的孤兒檔（另有 53MB 的 v4 版）。加 `assets/holiday/*.mp4` 約 67MB。
   → 若確認已全面改用 YouTube（mars-healing.html 已改 iframe 嵌入 YouTube），可直接清掉省 666MB。

### 🟡 P1 — 有空要收

3. **`pages/order-history.html:494` 連到不存在的 `review.html`**
   「前往評價此訂單商品」按下去會 404。這是全站唯一一個真實斷鏈。

4. **34 頁中只有 1 頁有 Open Graph 標籤**
   只有 `mars-healing-intro.html` 有 `og:title/description/type/url` + `og:image`（1 條）。其餘 33 頁分享到 LINE/FB 時，預覽文字仍會抓頁面內的裝飾性英文——正是 09-11 那次修掉的問題，但只修了 1 頁。

5. **25 / 34 頁未引入 `js/nav.js`**
   只有 8 頁（cart / category / checkout / holiday-form / holiday / mars-healing-history / order-history / order-success / product-detail）有載入。沒載入的頁面不會顯示登入狀態、也不會更新購物車角標。

6. **7 個孤立頁面**（沒有任何頁面連結過去，只能靠手打網址）
   `holiday.html`、`holiday-select.html`、`mars-healing-admin.html`、`mars-healing-detail.html`、`order-success.html`、`pwreset.html`、`reset-password.html`
   ※ 其中 admin 類可能是刻意隱藏，但 `holiday.html` / `order-success.html` 看起來是該被連到的。

### 🟢 P2 — 技術債

7. **70 個檔案用 Tailwind Play CDN**（`cdn.tailwindcss.com`），其中 18 頁還各自內嵌一份 `tailwind.config`（約 90 行重複）。另有 `js/tailwind-config.js` 只被 10 頁引用 → 三套配置並存。
   官方明講 Play CDN 不建議用於生產環境（每次載入都要 JIT 編譯）。

8. **根目錄有兩個開發草稿忘了收**
   `_live_checkout.html`（16KB）、`_v_checkout_new.html`（23KB）用 `../` 相對路徑，在根目錄開會全部 404。應移入 `pages/` 或刪除。

9. **Supabase publishable key 明文寫在 `js/supabaseClient.js:29`**
   anon/publishable key 本來就是設計給前端的，不算外洩；但真正的防線是 RLS。`backend/mars_healing_production.sql` 的 admin 策略用 `auth.jwt() ->> 'email' = '2022lingyun@gmail.com'` 硬編管理員信箱——可運作，但換管理員要改 SQL。
