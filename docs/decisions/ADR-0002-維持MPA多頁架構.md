# ADR-0002 · 維持 MPA 多頁架構（不轉 SPA）

- **狀態**：✅ 已決策 —— **採 A（維持 MPA 33 頁）**
- **日期**：2026-09-13（Phase 3 開工前拍板）
- **決策者**：族族（由主理人呈三案，四案全數選 A／推薦案）
- **上游**：`docs/briefs/2026-09-13_網站重寫.md`（已凍結，Q2② 純靜態）
- **影響**：H1 共享基座的導覽與路徑寫法、H3 連結圖的形狀、部署方式（Vercel 靜態）

---

## 背景

現況 33 個獨立 `.html`，彼此以相對路徑互鏈（`./soft-power-healing.html`、`../js/...`）。SPA 化的動機通常是「元件共用、切頁不刷新」，但本專案的共用邏輯已經靠共享 `js/`（supabaseClient / nav / config）達成，轉 SPA 的收益極低。

## 選項

### A. 維持 MPA 多頁（✅ 採用）
- 做法：24 頁重寫後仍各自獨立 html；跨頁狀態（登入後回跳）沿用 `localStorage` + 查詢參數
- 代價：每頁需自行引入基座四件套（base.css / db.js / nav.js / meta.js）——由 `CONTRACT.md` 範本固定
- 優點：與 Q2② 純靜態零衝突；Vercel 部署不變；任一頁壞了不拖垮全站；Playwright 逐頁冒煙可直接沿用

### B. 改 SPA 前端路由
- 做法：引入 hash/history 路由，33 頁收成單一入口
- 代價：需要建置流程（與 Q2② 直接衝突）、首屏 JS 變大、LINE 內開相容風險、斷鏈檢查邏輯重寫
- 結論：本專案無此需求

## 決策

採 **A**。H1 基座以「每頁固定引入四件套」為契約；H3 連結圖按「html 檔 = 節點、href = 邊」的有向圖建立。

## 連帶影響

- 路徑工具 `getPathTo()`（已存在於 supabaseClient.js）上升為基座契約的一部分，24 頁不得自行拼相對路徑
- 跨頁傳參一律用查詢字串（`?id=`、`?notice=`），禁用 localStorage 傳業務資料（登入回跳鍵 `wave_redirect_after_login` 為已核准的唯一例外）
