分析對象：
- `pages/admin-summary.html`（七七地赦管理結案總表）

## 0. 一句話結論

**權限防護是對的（RLS 有做），但同一份資料存在「內部版」與「呈總部版」兩套數字，呈總部版金額較低、異常區塊被隱藏——這需要先確認是不是刻意設計。**

## 3. 🔴 紅色問題

### 3.1 同一份資料、兩套數字：呈總部版金額較低

`admin-summary.html` vs `admin-summary-headquarter.html` 的實付金額計算：

```js
// 內部版（admin-summary.html:162-166）
if (NO_DISCOUNT_AGENTS.has(name)) { total += agentTotal; return; }
total += SPECIAL_PAID_AGENTS.has(name) ? Math.round(agentTotal * 0.9) : agentTotal;

// 呈總部版（admin-summary-headquarter.html:180）
total += SPECIAL_PAID_AGENTS.has(name) ? Math.round(agentTotal * 0.75) : agentTotal;
```

`admin-roster.html` vs `admin-roster-headquarter.html` 同樣：

```js
// 內部版:448
const rate = 0.9;   // 實付 90%
// 呈總部版:450
const rate = 0.75;  // 實付 75%
```

完整差異對照：

| 項目 | 內部版 | 呈總部版 | 影響 |
|---|---|---|---|
| 特殊實付率 | ×0.9 | **×0.75** | 呈總部金額少 15 個百分點 |
| 顏瑞蘭 | `NO_DISCOUNT_AGENTS`，算 **100%** | 列入 `SPECIAL_PAID_AGENTS`，算 **75%** | 同一人兩版差 25% |
| 幣別符號 | `NT$`（summary） | `$` | 呈總部版去掉國別代碼 |
| 三、異常與待辦 | 顯示 | **`.section:nth-of-type(4){display:none}`** | 呈總部看不到缺件/待辦 |
| 匯款後五碼 | 顯示於代理人名旁 | **移除** | 呈總部看不到對帳資訊 |

**這是這組頁面最需要確認的事。** 若為刻意（給總部的簡化對外報表）則沒問題；若不是，屬帳務風險。

### 3.2 管理員 Email 硬編碼在 4 個前端檔源碼

const ADMIN_EMAILS = ['2022lingyun@gmail.com'];
// admin-summary.html:91 / admin-summary-headquarter.html:100

- **風險**：管理員帳號成為明確的釣魚／暴力破解目標；且**只有一個管理員，沒有備援帳號**

## 4. 🟠 橙色問題

### 4.1 admin 頁無 noindex，線上公開可存取

```
https://wave-art-mall.vercel.app/pages/admin-roster.html → HTTP 200
```

4 頁全部 `grep -c "noindex"` = **0**。雖然資料本身受 RLS 保護抓不到，但：
- 搜尋引擎可收錄這 4 個管理後台路徑
- 暴露這是一套管理系統（結構、頁名、管理員 email）

### 4.2 98% 程式碼重複，且已出現不一致

`admin-roster.html` vs `admin-roster-headquarter.html`：461 行，**diff 只有 7 處**
`admin-summary.html` vs `admin-summary-headquarter.html`：207/220 行，diff 約 15 處

重複帶來的實際後果已經發生：
- `admin-summary.html` 用 `money()` → `NT$`
- `admin-summary-headquarter.html` 用 `money()` → `$`
- 兩個 roster 都用 `$`

改任何金額邏輯要同步 4 個檔案，漏一個就是兩套數字對不上。

## 5. 🟡 黃色問題

### 5.1 全表讀取，無分頁保護

```js
await supabaseClient.from('orders').select('*')
  .or('identity_type.not.is.null,customer_note.ilike.%特赦方案%')
  .neq('status','已取消')
  .order('created_at',{ascending:true});
```

4 頁皆無 `.limit()`。`roster` 的 `PAGE_SIZE = 10` 只是**列印分頁**，資料是一次全撈進瀏覽器。
目前資料量小無感，量成長後會拖慢。

### 5.2 未登入行為不一致

| 頁 | 未登入時 |
|---|---|
| admin-summary | 跳轉 `pages/auth.html` |

| admin-roster | 跳轉 `pages/auth.html` |
| admin-roster-headquarter | 跳轉 `pages/auth.html` |

### 5.3 敏感個資欄位（清點）

`recipient_name`（姓名）、`phone`（電話）、`street_address`（地址）、`student_number`（學號）、`age`（虛歲）、`total_amount`（金額）、`agent_name`（代理人）

## 6. ✅ 做得好的（這組最紮實的部分）

### 6.1 RLS 是真的有做

```sql
-- backend/supabase-schema.sql:365
CREATE POLICY "Admins can view all orders"
    ON orders FOR SELECT
    USING ((auth.jwt() ->> 'email') = '2022lingyun@gmail.com');
```

- 用 `auth.jwt()`（**不可由前端偽造**），不是 `auth.uid()` 或前端傳參
- 一般用戶只能看自己的單：`USING (auth.uid() = user_id)`
- `backend/holiday_admin_patch.sql` 有同步版本，可對線上執行

→ 即使有人看懂前端邏輯、直接打 REST API，也拿不到別人的訂單。

### 6.2 XSS 防護完整

`createRow()` 每一個欄位都過 `escapeHtml`：

```js
<td>${escapeHtml(order.recipient_name || '-')}</td>
<td>${escapeHtml(order.phone || '-')}</td>
<td>${escapeHtml(order.street_address || '-')}</td>
```

`escapeHtml` 有正確定義（`admin-summary.html:204`），覆蓋 `& < > ' "` 五個字元。

### 6.3 其他

- 有載入中狀態、錯誤訊息、空狀態、無權限提示（`#no-permission`）
- 列印樣式精細：`@page` A4 直式（內部）/ 橫式（呈總部）、`break-before:page`、專用 print CSS
- roster 有分頁頁碼「第 N 頁 / 共 M 頁」
- 舊資料相容有做：`customer_note` 用 regex 解析 `身分:` / `虛歲:` / `代理人:`（無 `identity_type` 欄位的舊訂單也能顯示）
