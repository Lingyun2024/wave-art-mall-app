## 1. 目標與交付

- **目標**：把 WAVE ART MALL 從「AI 逐步疊出來的 33 頁」收斂成「有機器可驗收標準的站台」
- **最終交付物（可驗收）**：
  1. 可跑的品質門檻：`npm run lint` / `check:links` / `check:html` / `test:e2e` / `build` 五條指令，紅燈即不可合併
  2. 一份凍結的資料契約 `docs/data-contract.md`（表 + RLS + trigger 清單）
  3. 重寫後的頁面與一份連結圖，**零孤立頁、零斷鏈、零品牌殘留**
  4. 發布後的線上站台，與本地逐位元組一致
- **範圍外（明確不做）**：
  - 不動 Supabase 的既有資料（products / orders 的真實訂單）
  - 不改已確認的刻意命名（例：`執執登記名冊`，2026-09-12 已查證為用戶主動修改）
  - 不引入後端伺服器（維持純前端 + Supabase）

## 2. 風格與約束

- **技術棧 / 既有規範**：純靜態 HTML + Tailwind（Play CDN）+ Supabase JS SDK；**不打包**（Q2② 已拍板），只加檢查工具
- **性能**：任何單頁首屏資源 < 1 MB；字型必須 subset（2026-09-12 已將 20.1 MB → 153 KB，此標準須保持）
- **兼容**：手機優先（LINE 內開為主要情境）
- **安全**：
  - 金額一律由 DB 計算，前端算的金額不得入庫（`backend/order_amount_guard.sql`）
  - 管理後台維持 RLS 白名單，前端白名單只作 UX
  - 所有使用者輸入渲染必過 `escapeHtml`
